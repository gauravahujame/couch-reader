# Implementation decisions

Date: 3 November 2026

## Platform and renderer

- Native Kotlin Android TV app, one Gradle app module. Native Views own the library, focus, import screen, dialogs, and reader overlays. No Compose or dependency injection framework.
- Minimum API 26, compile/target API 35. These are provisional until the actual TV model and OS version are supplied. The repository contains no device inventory or user books; reflowable DRM-free EPUB remains the documented input assumption.
- EPUB.js **0.3.93**, vendored in `app/src/main/assets/reader`, BSD-2-Clause. Original license is bundled. Its CFI locators, pagination, navigation, themes, and images sit behind `ReaderEngine`. Upstream: https://github.com/futurepress/epub.js/tree/v0.3.93 . The npm release is old; this is a provisional engine selection pending the physical-TV compatibility gate, not a claim that that gate has passed.
- Use an unpacked, validated OPF, avoiding JSZip and a second in-memory decompression step. EPUB.js owns pagination and CFIs. Book markup has scripts, event handlers, active embeds, inline CSS, and external styles removed. Publisher formatting is deliberately normalized, as permitted by the spec.
- Literata variable font, bundled under SIL Open Font License 1.1, for offline rendering. Source: https://github.com/google/fonts/tree/main/ofl/literata . Native controls use the platform sans-serif font.
- Six text sizes: 24, 28, 32 (default), 36, 42, 48 CSS pixels (replaced 12 November 2026 by 14–48 px, default 16; see the last section). Warm paper / forest ink or dark forest / warm ivory. Reader viewport uses 7% margins and caps column width at 1,180 CSS pixels. Final sizes require couch testing.

## Import and private storage

- NanoHTTPD 2.3.1 (BSD-3-Clause) provides a session-only local HTTP server on an ephemeral port. Browser sends one raw file body, avoiding multipart buffering. QR encoding uses ZXing core 3.5.3 (Apache-2.0). Sanitization uses jsoup 1.18.3 (MIT).
- Pairing: 192-bit SecureRandom token, constant-time comparison, monotonic 10-minute expiry; new session invalidates old token and closes old listener. Stop on screen exit/background. Token never enters app logs.
- Limits: 50 MiB compressed, 200 MiB expanded, 16 MiB per entry, 4,000 entries. Reject duplicate paths, traversal, encoded archive paths, external XML entities, encryption/DRM, right-to-left progression, fixed layouts, remote manifest resources, missing spine resources, and unsupported spine media.
- Keep sanitized resources only in app-private persistent storage. Source upload is staged in private cache and deleted after validation. Content hash is over original upload bytes, so identical imports deduplicate.
- One SQLite database with version 1, unique content hashes, foreign keys, transactional catalog insertion, and cascading position deletion. Finalize directories before catalog insertion; startup reconciliation removes orphan directories and temporary files and drops entries with missing package files. Future schema changes require explicit migrations.
- Locator JSON: `{version:1,format:"epub",cfi,href}`; position writes are queued after each completed relocation, independently per book. They do not rely on an Activity exit callback. Preferences persist globally.

## Explicit gate limitations

The documents require a renderer spike on the actual TV before finalizing compatibility. Hardware is unavailable, so implementation proceeds provisionally with automated fixtures and a buildable APK. The physical-device renderer gate, 20-minute couch session, phone/desktop LAN upload checks, API-26 verification, and measured reopen/page-turn targets remain release blockers. Do not equate a host-browser engine test or successful APK build with passing those checks.


## 5 November 2026 update

- User explicitly requested PDF upload and reading in addition to the mobile and TV UI fixes. Android `PdfRenderer` is the PDF engine; no extra PDF library or WebView scripting is used. PDF pages render on a single worker thread with a bounded 12M-pixel raster; fixed-layout pages fit the column width and scroll vertically. Left/Right page turns are sequential; Up/Down scrolls; EPUB behavior is unchanged. PDF controls show the fixed-layout explanation and themes, without pretending that EPUB font resizing or chapters apply. Dark mode inverts the PDF page, including its images.
- Catalog schema 2 adds `format` with default `epub`; an explicit ALTER migration preserves schema-1 books and positions. The legacy database column named `opf` remains for compatibility but is exposed as the format-neutral `contentPath`. PDF content is stored as `book.pdf` in its own atomic private book directory. Original-byte SHA-256 deduplication applies to both formats.
- PDF locator schema 1 stores `{version:1,format:"pdf",page,offset}`. EPUB CFIs keep their existing schema. Offsets are normalized within the current page's scrollable region, not viewport page numbers. Password-protected/malformed PDFs receive an explanatory failure without a catalog entry.
- Pairing tokens rotate atomically on the existing listener every ten minutes while Add book stays visible. Refresh is deferred while receiving a file; leaving/backgrounding still closes the server. Codes and readable URLs update together, and the TV stays awake while waiting. Old mobile pairing pages need a new scan after their token expires.
- Native Literata headings use explicit line heights with font padding/fallback spacing disabled, the empty-state introduction has a weighted column, and its underline is drawn rather than dependent on glyph alignment. SquareQrView enforces equal measured width and height. The original TV QR measured 368 × 368 px; there was no distortion in that capture.
- The upload page uses constrained fluid spacing/type, full-width file input and buttons, minimum-width guards, dynamic viewport-height fallback, and an explicit PDF+EPUB extension/MIME filter. Native phone pickers are controlled by the browser/OS; both registered PDF MIME and extension forms are supplied.


## Fullscreen reading — 5 November 2026 (v0.2.1)

At the user's request, the reading surfaces now occupy the entire display. EPUB uses a 100% width/height viewport with no column-width cap, body padding, or pagination gutter. PDF removes the native outer frame padding and scrollbar. PDF page aspect ratio and the document's own printed margins remain intact. This supersedes the earlier capped reading column/safe-margin choice for book rendering; native controls and overlays retain their existing layout.

## Global settings — 6 November 2026 (v0.3.0)

Settings is a native, opaque full-screen page above the existing reader, retaining its measured viewport and engine. Back returns directly to reading; library access works even with no books. Option rows own Left/Right/OK and save immediately. Preferences schema 2 defaults missing spread/sleep fields to Off/30 minutes, preserving size/theme, and writes with apply(). Theme remains a reader quick action.

EPUB auto spread uses a 900 CSS-pixel threshold and a 40px pagination gap when wide; single-page remains fullscreen without a gutter. The first visible CFI is redisplayed after preferences change. PDF ignores EPUB size/spread.

The inactivity handler releases KEEP_SCREEN_ON after 15/30/60 minutes since the last key, including while reader settings or controls are visible. Never has no timeout; Add book keeps its existing behavior. The timeout does not force power-off or alter the TV's system settings. Backgrounding cancels the handler and clears the flag.

About computes catalog count and private book-file bytes off the main thread. Instrumented tests may be built with -PisolatedTestApp to use dev.couchreader.qa and keep real TV books/preferences separate.

## Settings review fixes — 7 November 2026 (v0.3.1)

EPUB preferences retain a pending `{cfi,href}` passage across consecutive reflows. Relocation events save that passage instead of successively earlier page starts. Explicit page turns and chapter navigation clear it. This supersedes saving the first visible CFI during preference-only reflows; normal navigation still saves the new first visible position.

Text size and sleep options clamp at their endpoints. Both text-size controls show CSS px; spread help refers to wide screens. Missing package version names display Unknown. Back to the library restores focus to Settings. Reader errors during settings are deferred until returning to reading; boundary events cannot open overlays and ready events cannot steal settings focus.

Settings tests use typed module-internal Activity members rather than private-name reflection, and wait on conditions/renderer queue completion. Persistence is verified by polling and parsing the on-disk preferences XML after apply(), not by treating Activity recreation as a process restart.

## Chapter/progress and location cache — v0.4.0, 7 November 2026

- Controls show live chapter/progress; cards use a non-focusable native horizontal bar. EPUB TOC links resolve relative to the navigation document and match spine sections; fragment entries compare their CFI against the current passage. Unlisted sections use Section N. PDF displays Page X of Y and retains its existing format-specific locator.
- One hidden WebView/book instance at a time runs the background index queue after reader-ready or from the library for previously opened EPUBs lacking progress. A reader that already loaded a valid cache skips the index worker entirely. It never renders publication content or shares the foreground book's Section objects: locations.generate() unloads sections. EPUB.js generate(1600) is asynchronous and yields for 100ms between sections. It stays outside the reader serial command queue and continues if the user returns to the library. This is cooperative background JavaScript, not a claim that EPUB.js's synchronous parsing inside a single large section runs in a Web Worker. Activity destruction cancels unfinished work; an interrupted uncached job retries on a later open.
- Cache book-locations/<book-id>.json (served virtually as locations.json) is outside publication resources to prevent filename collisions, and is bound to the book's original content hash. Version 1 identifies EPUB.js 0.3.93 / 1600-character locations over sanitized content; change the version when this format/algorithm changes. AtomicFile writes/validation run on the JavaScript bridge thread, off the native UI thread, under the repository deletion lock, with a 32MiB bound. Missing/stale/corrupt cache is regenerated, completed cache is loaded without generating again, and book deletion removes it naturally. Cache creation never changes resume positions.
- Catalog schema 3 adds reading_progress (fraction and chapter only), with explicit upgrade from earlier schemas and foreign-key cascade. Existing positions/EPUB CFI payloads remain untouched. Fraction is derived display data, not a viewport/page locator. Reflows use the pending original CFI anchor established in v0.3.1, preventing drift of displayed progress. About storage includes the location cache.

Hidden index views dispatch bridge callbacks through an explicit main Handler; View.post would defer completion until window attachment. The TV regression test caught this before delivery.

## PDF stays single-page — 11 November 2026

The two-page spread setting stays EPUB-only by choice, not because of a platform limit. PdfRenderer opens one page at a time, but the single PDF worker could render two pages in turn and place them side by side within the existing 12M-pixel bitmap cap. The reason is readability at TV distance. A spread must fit each page to the screen height: a portrait A4 page at 1080px tall is about 764px wide, so its text is about 2.5× smaller than the current full-width page (up to 1920px) that Up/Down scrolls. At couch distance that is too small for ordinary book print. Revisit if image-heavy PDFs (comics, picture books, large-print scans) become a target, as an off-by-default PDF option that falls back to one page when two will not fit.
## PDF Go to page — 11 November 2026
PDF controls replace the EPUB Chapters button with Go to page. It opens a single page dial (`PageDial`) instead of a button per page, so the popup has the same size for 20 pages or 2,000. ← / → move one page and ↑ / ↓ move a larger step: 10 pages, rising through 25, 50, 100 and 250 so the whole book takes about 20 to 25 presses. Holding a key repeats at most every 140ms so the number stays readable, number keys type a page directly, and OK opens it. A track under the number shows where the chosen page sits, with a gold tick at the page being read. The popup spells out every key, so nothing relies on discovering hidden behaviour. TalkBack reads the dial as an adjustable control ("Page 30 of 48"); its scroll actions move one page and double-tap opens. A jump opens the target page at its top. A jump requested while a page is still rendering waits for it and replaces any queued turns.
This replaced a first version that drew a grid of page buttons, ten per row, which grew with the page count and overflowed the popup on a 48-page PDF.
The PDF's own outline (bookmarks) is not used yet. `PdfRenderer` does not expose it, so it needs the catalog's `/Outlines` tree, destination resolution (direct, named `/Dests`, and the `/Names` tree) and a page-tree walk to map page objects to indices. The `PdfMetadataReader` lexer and its one-pass object index can do the reading. Many PDFs have no outline at all, so the dial stays as the fallback.
## Popup layout — 11 November 2026
`overlayPanel` keeps the title fixed and scrolls only the body, and the card is capped at the screen height minus 7% margins top and bottom, so long chapter lists keep the title and the card's rounded edges on screen. The returned panel is the scrolling body; the title is not one of its children. In reading controls the Warm light option rests in the reader's light page colour (`Palette.paper`, `#f5f0e5`) instead of button white.
## Book titles and authors — 11 November 2026
PDFs used to show the upload filename and "Unknown author". `PdfRenderer` exposes no metadata, so `PdfMetadataReader` reads the XMP `/Metadata` stream (preferred, Unicode by definition) and the trailer `/Info` dictionary itself, including objects in compressed object streams. It indexes the file in one forward pass over a memory-mapped buffer; rescanning per lookup was too slow for 50 MiB files. Encrypted files skip `/Info` because their strings are ciphertext.
Embedded values are often generator noise ("Microsoft Word - Document1", "Administrator", office routing codes), so `BookMetadata` accepts them only when they read like a real title or name; otherwise the title comes from the filename with separators, download-site tags and duplicate markers removed. An unknown author is stored as an empty string and every screen omits the line, rather than printing a placeholder. Run-together names ("UnderstandingHarnessEngineering") are not split, because that breaks names like "JavaScript".
Schema 4 adds `books.metadata`, the version of these rules that produced a row. `BookRepository.refreshMetadata()` re-derives older rows once at startup; bump `METADATA_VERSION` when the rules change.
## Read aloud — 11 November 2026
- **Voice.** Android `TextToSpeech` with whatever engine the TV has (the OnePlus TV ships Google's). It is offline when the voice data is installed, needs no library, and reports word ranges (`onRangeStart`), which the page-break turn uses. Cloud voices would break the no-cloud, no-account promise; bundled neural voices (Piper/Kokoro via sherpa-onnx) were left for later because of APK size and slow TV CPUs.
- **Unit is the sentence.** Speaking from a visual line would start mid-sentence, and EPUB lines move whenever the text size changes. `ReadAloud` keeps one sentence queued behind the one being spoken (`QUEUE_ADD`) so there is no gap, and tags every utterance with a speech and page generation so callbacks from stopped speech are ignored.
- **Highlight before voice.** Entering read-aloud only highlights; OK speaks. This is what lets the reader move to a sentence first. OK therefore plays and pauses while read-aloud is on, instead of opening controls; Back leaves read-aloud, then OK opens controls as usual. *Superseded 12 November 2026 for the Read aloud button: see below.*
- **EPUB sentences.** `reader.js` walks each section's text nodes, groups them by block element, and splits with `Intl.Segmenter` (regex fallback). Each sentence is a DOM `Range`, cached per section document, so the book markup is never changed and CFIs stay valid. The page's sentences are those intersecting EPUB.js's visible start/end CFIs; `continued` marks one that began on the previous page, and `visible` is how much of the last one fits. The highlight uses the CSS Custom Highlight API (WebView 105+; the TV has 156), falling back to an EPUB.js annotation on older WebViews. Footnote reference markers (`sup a`) are skipped.
- **PDF text.** `PdfRenderer` has no text API before Android 15, so PDFs use PdfBox-Android 2.0.27.0 (Apache-2.0). It brings BouncyCastle 1.72 transitively, for encrypted PDFs the app already rejects; the debug APK is now 11 MB. Excluding BouncyCastle would shrink it but risks class-loading failures inside PdfBox, so it stays. `PdfText` strips one page on its own worker thread, keeps each glyph's box, rejoins words hyphenated across lines, and splits with ICU `BreakIterator`. The highlight is a separate view over the page image, outside the dark-mode inversion filter, with one box per printed line. A sentence that crosses a PDF page break is read as two parts. Scanned PDFs have no text layer and are skipped page by page; OCR is out of scope.
- **Page turns.** Engines emit `page` whenever a page is shown. `ReadAloud` tells its own turns (end of page, word past the break, crossing with ↑ / ↓) from the reader's (← / →, Go to page, chapter, reflow): after the reader's own turn the voice restarts on the new page; after its own it carries on.
- **Voice picker.** Settings lists `TextToSpeech.getVoices()` filtered to offline, installed voices, dropping Google's `<locale>-language` aliases that duplicate a real voice. Engine names (`en-in-x-ena-local`) mean nothing and the API gives no gender, so rows show language plus a number, and every change plays a sample. Switching voice makes Google TTS load a synthesizer, which can take seconds, so `VoiceSamples` records each voice's sample once with `synthesizeToFile` into `cacheDir/voice-samples/` (keyed by a hash of voice name and sample version) while Settings is open, and plays the file with `MediaPlayer`. A voice whose sample is not recorded yet speaks it live, interrupting the recording, which is requeued. Samples are English except for Hindi voices. The saved voice is the engine voice name (`voice` preference); `ReadAloud` applies it at start and on change, falling back to the default voice when it is no longer installed.
- **Only while open.** No foreground service, `MediaSession` or notification. `onStop` pauses and closing the reader shuts the engine down. Revisit if screen-off listening is wanted.
- **Controls layout.** Read aloud is the first control in the reading controls. To keep the card within a 1080p screen without scrolling, Chapters / Go to page and All settings now share one row, and the popup body clips itself (its scrolled rows had painted over the title).
- **Highlight placement.** EPUB.js's visible start CFI can sit a word late. Which screen a sentence is on comes from where its first and last characters are laid out (column index = left edge ÷ `layout.delta`), with the CFI comparison as a fallback when a character has no box.
- **Diagnostics.** `CouchReadAloud` log lines record voice init status and state changes with sentence indexes only, never book text.
- **Position.** Resume positions are unchanged (page-level). A per-sentence resume would need its own locator and is not worth it while re-entering starts at the page top.
## Read aloud starts on its own, smaller text, multi-file upload — 12 November 2026
- **Read aloud plays once the voice loads.** The user found the stop in "Paused" after "Getting the voice ready…" confusing. The Read aloud button now starts the voice from the first sentence on the page, the same path as the remote's Play key. Up/Down, OK and Back work as before, so choosing another sentence is pause, move, OK. `ReadAloud` stays in PREPARING until the voice speaks, instead of passing through PAUSED, so the pill never flashes "Paused" on the way; it settles in PAUSED only when it will not start (no text on the page, audio focus refused, paused while preparing).
- **Text sizes.** The old 24–48 CSS px list started above PDF text: on the 1080p TV (density 2) 24 px Literata is 48 device pixels, while a fit-to-width PDF's body text is about 32. The list is now 14–48 px with 16 px the default, which matched the user's PDF in side-by-side screenshots. The preference still stores an index, so the stored `version` went to 3 and older indexes (into the old list) reset to the default rather than being mapped by px value: mapping would have kept 24 px, which the user had already said was too large.
- **Multi-file upload.** The server still takes one raw file per request (no multipart, one import at a time). The page sends the chosen files sequentially and stops after a 403 or network error, since later files would fail the same way. The TV shows each arrival in a card and a toast, because the old status line change was easy to miss from the couch. The instructions column now clips itself (it had painted over the masthead once the card made it scroll) and carries 10dp of padding, offset by a negative margin, so focus shadows are not clipped.
## EPUB margins, black dark theme, Settings freeze — 12 November 2026
- **Margins.** The `#pages` element that EPUB.js renders into is sized `100% − 14vw` by `100% − 12vh` and centred, instead of padding the book's body: EPUB.js measures columns from its container, and body padding would throw off pagination and page turns. Read-aloud placement is unaffected because character boxes are measured inside the section iframe.
- **Dark is black.** The EPUB dark background was dark forest (#202822) while an inverted PDF page is black, so the two looked different. Both now use black; the PDF frame behind short pages matches too.
- **Settings freeze.** Leaving Settings soon after opening it froze the app for up to 10 seconds. Settings creates a `TextToSpeech` for the voice samples, and until it reaches `onInit` the platform holds the instance's start lock while it sets up the engine connection, which Google TTS can take seconds to do. `stop()`, `shutdown()` and `setSpeechRate()` wait on that lock, so calling them on the UI thread blocked it (logcat: "stop failed: TTS engine connection not fully set up", then "Skipped 562 frames"). Engines are now released on a short-lived thread, and stop/rate calls are skipped before `onInit`. Read-aloud had the same trap when stopped while "Getting the voice ready…".
- **Read-aloud highlight without overlap.** The EPUB highlight used the CSS Custom Highlight API, which paints the font's full ascent and descent; on tight lines (headings at 1.2 line height) neighbouring lines overlapped and the translucent tint doubled into a darker band. The highlight is now one rounded box per printed line, built from the sentence range's client rects, with any vertical overlap between neighbouring lines split at the middle and a 2px gap left. The boxes sit in a layer appended to the section's `<html>` (outside the book's body, so CFIs and the sentence walk are unaffected) and blend instead of covering the text: multiply on the light page, screen on the black one. The layer must not get a `z-index`, which would isolate it and turn the boxes opaque. The PDF marker applies the same overlap split to its per-line boxes.
